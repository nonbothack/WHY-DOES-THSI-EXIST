SPEC_01 // C_NODE_MEMORY_LAYOUT

Memory Model & Node Representation

Every contact record is allocated at runtime via malloc(sizeof(struct Contact)). Nodes are chained strictly via a 64-bit forward pointer.

/* Exact C99 Node Memory Blueprint */
struct Contact {
    int id;                 /*   4 Bytes  [Offset: 0x00] Unique record index */
    char name[50];          /*  50 Bytes  [Offset: 0x04] Contact full name */
    char phone[20];         /*  20 Bytes  [Offset: 0x36] Preserves leading zeroes */
    char email[60];         /*  60 Bytes  [Offset: 0x4A] Optional email string */
    /* 2 Bytes compiler alignment padding to 8-byte boundary */
    struct Contact *next;   /*   8 Bytes  [Offset: 0x88] 64-bit forward pointer */
};

01 // HEAP_ALLOC

Strict Dynamic Allocation

Nodes are dynamically allocated via malloc(sizeof(struct Contact)) and released via free() upon deletion or shutdown, ensuring zero memory leaks.

02 // IN_PLACE_SORT

In-Place C Bubble Sort

Alphabetical sorting executes directly in C by traversing pointer links and swapping node payloads without reallocating or breaking chain integrity.

Non-Volatile Disk Sync

The system maintains non-volatile persistence via contacts.csv. Any mutation (add, edit, delete, sort) immediately synchronizes with disk storage.
